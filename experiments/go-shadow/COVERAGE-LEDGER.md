# Go IAST taint tracking — coverage ledger

Derived from `stock-vs-orchestrion.html` (Go IAST research report, July 2026) and then
**resolved empirically**: every case the report marked *Not proven* was handed to a dedicated
agent that wrote a real, executing test and recorded the measured outcome.

Cells marked ✎ were measured in this exercise. Unmarked cells are the report's original claims.

> **Provenance warning — half of this matrix was never measured, and unmeasured cells are written in
> the same confident voice as measured ones.** A `✎` on a verdict is the ONLY thing that marks a cell
> as empirically checked. 149 of the 310 prototype cells have no `✎`, and 90 of those still say
> "Verified…" or "E2E-tested…" because that wording was inherited from the source report rather than
> earned here. Read any cell without `✎` as an UNVERIFIED PRIOR CLAIM regardless of how it is phrased.

> **GM methodology warning, revised — the two columns are not measured to the same STANDARD, but
> that is an assertion gap, not a precision gap. Do not compare their win counts as if they were.**
> The Orchestrion harness asserts, for every case, the exact sink value, the exact byte ranges, and
> the COMPLETE report multiset, so any missing, mismatched or extra report fails the case. The
> patched-Go suite asserts, by default, only the NUMBER of sink reports (`strings.Count(output,
> dirtyReport) != DirtyReports`). Of its 112 positive cases, **5 also assert exact byte ranges** via
> the optional `exactRanges` field (`exactbyteranges`, `exactsourceoccurrenceidentity`,
> `globalstringassignment`, `indirectosfunctionvalues`, `multiplesourcerootsets`), and **2 of those 5**
> — `exactsourceoccurrenceidentity` and `multiplesourcerootsets` — additionally assert exact
> source-range coordinates AND distinct source IDs, i.e. the full Orchestrion standard.
> **107 positive cases rest on the report count alone.** Neither the count nor the range assertion
> compares the sink VALUE, which Orchestrion does compare on every case.
> **Case 124 narrowed this, and only for the path it tested.** Case 124's change is REPORTING ONLY:
> `taintPrintRanges` walks the per-byte shadow bitmask the design has carried from the start and
> coalesces dirty runs, adding no propagation. So for the concatenation path case 124 exercises, the
> runtime already knew byte-exact positions and the suite simply never asked.
> **What that does and does not license.** It shows the reporting facility exists; it does NOT show
> that each of the 107 count-only cases propagates the CORRECT ranges, because nothing asserts them.
> This ledger records counter-examples in the same column: case 20 carries control-flow taint at
> header granularity, case 25 propagates runes coarsely, and case 126 marks conservative full-span
> positions. So the honest statement is narrower than the one I first wrote here:
> **the two columns are graded differently and their Win totals are not commensurable.** Orchestrion
> Wins mean "exact value, exact ranges, complete multiset, extra reports fail". Patched-Go Wins mean
> "the expected number of sink reports was observed". Its controls are real but PARTIAL, not
> universal: of 170 case descriptors, 29 run with instrumentation disabled and 29 run enabled over a
> clean path, and those controls are attached to some fixtures and not others — they are not present
> for every positive case. Do not subtract one total from the other.
> The remedy is cheap and demonstrated — adopt `exactRanges` across the existing fixtures, no new
> tracking required — but it has NOT been done, so the gap stands as published.

## How to run

```bash
# Lane A - Orchestrion, stock Go. 232 subtests, includes the -race pass.
go test -count=1 ./runtime/taint/...

# Lane B - patched Go, 170 subtests. TAINT_GO must point at a toolchain whose
# `go tool compile -V=full` contains "iast-taint-shadow-v28"; the suite refuses to run
# against an unidentified compiler rather than reporting a green no-op.
TAINT_GO=<patched-go> go test -count=1 ./experiments/go-shadow/suite

# Rebuild this report as HTML. Tallies are recomputed from the matrix, so a stale
# summary shows up as a mismatch instead of being carried forward.
go run ./experiments/go-shadow/report -o stock-vs-orchestrion.html
```

Rebuilding the Lane B toolchain from the durable patch, which is the only surviving copy of
the compiler and runtime work:

```bash
git -C ~/dd/golang/go worktree add --detach /path/to/go-taint-shadow-v28 e87b10ea2a
cd /path/to/go-taint-shadow-v28
git apply /path/to/orchestrion/experiments/go-shadow/go-taint-shadow.patch
cd src && ./make.bash
../bin/go tool compile -V=full   # must report: compile version go1.26.1 iast-taint-shadow-v28
```

**Coverage caveat that the exit code will not tell you.** Without `TAINT_GO`,
`TestRuntimeTaintFixtures` skips and the package still reports `ok`, so a plain
`go test ./...` exercises none of Lane B. `TestFixtureInventory` runs either way and fails on
fixture rot — an empty manifest, a case that omits `dirtyReports`, a case that rewrites
`TAINT_PATH` through `env`, or a fixture directory that contributes no cases — but it cannot
substitute for running the fixtures. Treat a Lane B run without the version line above as
producing no evidence at all.
